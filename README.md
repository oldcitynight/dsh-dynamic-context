# dsh-dynamic-context：动态上下文与受控请求通道

本地待提交入口：`/task-graph [任务说明]` 是本版本唯一的用户启用入口。模型不再根据任务规模自动询问或启用。不带说明时沿用当前任务；尚未选择时询问三种工作方式，已有任务图/完整模式选择继续有效。先前选择原生模式时，该显式命令重新询问。模式选择取消或历史图需要恢复时不发送新的执行请求。命令通过基础插件的通用可选接口接入，具体选择与联动提示仍由本插件实现。

本地待提交状态机已接通：路线登记 → 选择模式及规划后执行策略 → 独立预规划（开放 Bash）→ 双图提交并结束规划 → 程序串行调度与监督。默认启用 `interaction.orchestration: true`。已用真实 DSH 服务和 fake HTTP 后端回归；本次没有调用真实模型或发布新版。

本版本的规划与执行提示词支持开放任务：预规划从用户使用路径展开备选设计与组合约束，在既有报告里记录关键取舍；执行者在当前叶、原合同和权限内自主完善实现。推理强度继续默认为 `auto`，不新增思考额度或方案数量要求。组内终审根据本组目标读取原始成果文件进行校核；图级终审根据规划总目标与原始用户需求全面检查最终成果。单组复用时一次覆盖这两项职责。只读文件、目录与 ZIP 取证工具、标准示例及边界见 [分层协议](HIERARCHICAL-WORKFLOW.md)。各维护线的验证范围见 [验证说明](VALIDATION.md)，测试计数及安装包哈希见对应 Release 的签名记录。

## 已实现的范围

- 通过程序接口 `submit({ taskGraph, contextGraph })` 一次提交任务图、上下文节点和逐任务绑定。复用 `dsh-better-task-grapth` 的公开核心、持久化与 CAS；两张图及报告位于一个原子提交的私有文件中。
- 上下文节点可继承其他上下文节点。程序生成 ID，检查引用、循环和重复绑定；装配时按父节点先行的顺序去重展开，仅包含当前叶任务声明的上下文。
- 每个任务绑定自己的操作说明、上下文集合、前序报告和可见工具。报告继承只允许引用任务依赖中的前序叶任务，并在使用时核对已提交状态及原始执行记录的 SHA256。报告文本由程序原样复制。
- 宿主通过 `systemPrompt` 提供完整固定约束，通过 `allowedTools` 给出权限上限。上下文图不能声明 system/developer 角色，也不能扩大工具权限；模型侧工具可见范围和执行时限制使用同一份任务绑定。
- 每个任务使用独立历史，只继承明确声明的报告。`native-guarded` 将材料作为日志化用户消息交给 DSH；`direct` 使用插件私有的 system/user/assistant/tool 历史，记录实际发送字节的 SHA256。
- 完成的报告、上下文版本、实际请求、会话事件与带 hash 的执行记录持久保存。关闭运行器后可以继续尚未开始的任务。断流、取消、请求超时、输出截断、空报告和请求上限均保留 ACTIVE，阻止自动重放和依赖任务推进。普通与未知工具错误默认反馈给 Agent；仅命中插件可登记的工具错误规则时才阻塞整个任务，规则按内部工具 ID 和结构化错误参数精确匹配，详见 [工具错误策略](./TOOL-ERROR-POLICY.md)。原生前台终端已回收的命令超时会作为失败观察交回模型；同批后续调用暂缓，由模型先检查部分成果再决定下一步。
- direct 可显式启用持久检查点、协作式暂停和安全边界恢复，以及带原文归档的提取式历史压缩。已确认完成的工具不会因恢复而重放；结果未知的 HTTP 或工具调用继续阻塞。

## 请求校验

### 运行中共享上下文

在联合提案的 `contextGraph.nodes` 中为可更新的数据节点添加 `mutable: true`，例如 `{key:"reference_location",content:"docs/index.md",parents:[],mutable:true}`。通过现有上下文绑定将它分配给需要该事实的叶。在 direct 执行的 `state` 模块、宿主 `allowedTools` 和该叶的工具绑定中启用以下能力。

- `dynamic_context_shared_update({id, content, reason?})` 直接应用新内容，返回稳定 ID、递增版本及本次修改的回执。程序记录原值、各次修订和对应的叶与调用。修改即生效，无事实审核或审批步骤。
- `dynamic_context_shared_read({id, revision?})` 读取当前内容或指定历史版本，并返回最新版本号。新叶装入其所绑定节点的当前内容。正在执行的叶从工具回执取得更新，已发送的消息、旧报告及恢复时的初始上下文保留原版本。

共享条目是项目数据。调整任务范围、依赖、验收标准或工具授权由原有图修订渠道处理。旧版本已有的普通节点沿用静态语义，可在结构修订时为后续叶添加可更新的节点。报告修复继续装入完整的本叶执行证据。

### 请求契约

任务开始时固定上下文版本、宿主提示、初始任务消息、完整工具定义、模型路由和输出上限，生成请求契约 hash。原生通道在模型调用入口校验以下内容：

- 系统提示必须与宿主提供的完整策略一致，用户消息只能是本任务的初始材料；额外 user/developer 消息拒绝发送。
- 工具名称、描述和参数 schema 必须匹配任务快照；额外声明提供器或装配回调不能扩大或替换工具定义。
- 历史 assistant 内容必须对应本运行器观察到的模型输出，工具结果必须对应已记录的模型调用与实际工具执行结果，并保持调用配对及顺序。
- 模型、provider、输出上限以及包含系统提示、工具 schema 和历史的输入字符预算均参与检查。
- 在已安装适配器的 `onPayload` 入口再次核对 wire 消息与工具，并拒绝校验之后新增的适配器 hook 作用域。不具备此入口的适配器拒绝运行该原生通道。

原生插件侧的 `suppressAllRuntimeContext` 可以禁止注册运行时上下文补入，`complete` 可以替换最终系统提示；但 DSH 仍会收集工具提供器、求值其他系统段并运行装配监听器，可能因多个 complete 提示或提供器异常而失败。因此这组公共接口不能完全停用默认策略。`native-guarded` 用于兼容性验证，遇到冲突或输入不符合契约时停止，不能通过忽略错误来强行运行。

## 直接发送通道

`direct` 不调用 `systemPrompt.assemble/refreshContext`、`agents.followup`、`agent/pre-step`、`ctx.llm.stream` 或 PiAiAdapter。插件根据已经提交的上下文图构造请求，校验、序列化并记录请求后，通过明确配置的 endpoint 直接 POST。不会根据原生通道是否失败自动切换。只有显式启用下述原生压缩适配时，才允许一次服务端明确返回 `context_length_exceeded` 后的压缩恢复；未知请求、普通 HTTP 错误及工具效果不自动重试。可通过 `direct.generation` 显式固定 temperature、top_p、top_k、min_p、repeat_penalty、repeat_last_n、presence_penalty、frequency_penalty、seed；这些字段进入请求契约，不能覆盖模型、消息、工具或输出上限。

直接通道在每次 HTTP 请求前保存 SENT 记录；支持有大小上限的 SSE、工具参数分片、取消与超时。非正常结束、断流、不完整协议、重定向和错误响应均停止推进。凭据只能从显式配置的引用解析，不写入执行记录；指定引用缺失时拒绝发送。

直接通道仍通过 DSH 公共 `ToolRuntime.execute` 执行工具，保留审批和 guard，不直接调用工具函数。模型批次的工具名称、调用 ID、JSON 形状和参数 schema 在第一个工具产生效果前整体校验，原生运行时随后再次逐调用验证。工具身份、作用域与参数在执行前核对，嵌套或重复派发、工具中绕回原生模型 API、注册表热变更均会停止任务。

未配置 `direct.runtime` 时保留原 agentless 模式：不创建 Agent，只允许另列入 `direct.agentlessTools` 的工具，许可默认为空。此模式不能借用 Agent 专属沙盒和审批；不要把 Shell、PTC 或正式任务图提交工具加入该白名单。工具追加上下文和提前结案均拒绝传递。

agentless 模式的 `sessionId` 只是执行记录关联 ID；配置 `direct.runtime` 时，它对应真实的执行 Session。两种模式都以插件私有历史和实际 wire 字节为请求来源；没有冒充原生 replay token meter，实际 token 计量和性能收益需要另行验证。

## direct 执行服务迁移

非完整访问模式下，文件与搜索工具的路径及符号链接目标必须位于工作区内，需用这些工具回读的临时报告也应保存在工作区。`DIRECT_RUNTIME_PATH_OUTSIDE_WORKSPACE` 是执行前的路径拒绝：rc.23 通过工具反馈返回 `DEFERRED_NOT_EXECUTED`、被拒路径、工作区及准确的 `affectedCallIds`，让模型自行修改请求；不会执行被拒调用、擅自改写路径或重放先前成功操作。同批剩余调用整体延后，并纳入持久化检查点。私有路径访问等不允许的请求同样在执行前拒绝并反馈；当前用户指令、Goal、Plan 或工作目录变更、执行身份不一致、日志/证据完整性失效仍停止；仅主会话的权限/批准策略变化由热更新处理。未知工具效果不能作为“没有执行”的依据，也不会被宿主自动重放。

`direct-runtime.mjs` 通过公开 API 创建真实 Agent/Session，但只作为工具执行身份：不挂载整套 Web 预设、不启动原生模型循环；其 followup/inject/steer 被拒绝。工具在单独能力作用域中注册，worker 只继承任务绑定的子集，避免同一层注册的工具绕过限制。请求中的系统提示由宿主约束和显式事实生成，不调用默认提供器。

| 模块 | 已接入的能力 |
| --- | --- |
| `filesystem` | 原生 `read`、`write`、`edit`，保留原生原子写入、观察版本、错误与差异元数据 |
| `search` | 原生 `glob`、`grep`，使用真实 ripgrep 子进程 |
| `shell` | 原生前台 `bash`，保留真实工作目录、审批、取消和文件写沙盒；发送前要求完整沙盒能力，返回显式 exitCode 与沙盒事实 |
| `web` | 原生 `web_search`、`web_fetch`；使用宿主已配置的 Web 服务 |
| `skills` | 只暴露显式 `skills` 名单；`skill` 返回已加载正文及 hash，`requiredSkills` 在首次请求前加载 |
| `state` | `dynamic_task_status` 返回当前叶任务、声明报告引用和关联 Goal 的 ID/revision/phase；`dynamic_context_source_read` 读取当前尝试的压缩归档；不隐式复制完整目标和验收材料，不会完成 Goal |
| `registeredTools` | 显式接入宿主已经注册的工具，例如经过审核的 MCP 或历史读取适配器；定义和 schema 仍会固定和验证，不自动导入服务器提示词 |

每个 worker 设置独立的工作目录和原生执行身份。`runtime.sandboxMode`、`runtime.approvalPolicy` 默认为 `auto`，随主会话权限和批准策略变化；无主会话时沿用宿主默认策略。显式设置只能增加约束，父级 Plan 的只读含义继续生效。权限放宽从后续工具生效；权限收紧会取消当前工具或等待批准，并把原始回执与可能存在部分效果的说明交给模型，随后继续任务。已有工具效果不回滚、不重放。Goal、Plan、工作目录或当前 user/developer/system 输入变化仍走既有停止/引导流程。额外 Plan 只读分类只接受显式注册的外部工具，不能把已知写入或 Shell 工具重新标成只读。

共同规则包括项目根及适用目录的 `AGENTS.md` / `CLAUDE.md` 和 local 文件、宿主 DSH_HOME / DSH_AGENTS_HOME 的全局指令、时间与时区、任务身份和证据含义。可通过 `instructionHomes` 显式指定指令根；测试使用独立的合成目录。指令正文及来源 hash 固定保存，不插值、不静默截断。首次预检覆盖整个工具批次，后续每次调用前再校验尚未执行的部分。新增适用指令通过工具观察交付，`affectedCallIds` 标明未执行的调用；已完成的前缀有真实效果，不能重放。改变、删除已有指令或在已校验目录中新增指令文件会在下一调用前停止任务。文件工具按目标目录、Shell 按显式 workdir 发现规则，不解析任意 Shell 脚本内部的全部文件访问。

只有经许可的重复工具提醒会转换为带来源的 tool 观察，不追加默认 user 消息；未知附加上下文、提前结案、多媒体结果仍拒绝。外部工具需要自己的参数和权限约束，不能仅凭名字宣称它已受文件沙盒管理。当前原型仍使用文本模型协议；技能理解、真实 MCP/历史后端、真实 Web 服务及实际模型表现须分别验收。

## 工作区与执行记录分离

执行服务模式要求 `directory` 位于整个 `projectRoot` 之外，即使 `runtime.cwd` 只是项目子目录。`storageRoot` 给出已有、规范化的状态根目录，`directory` 必须是它的真实子目录；状态记录、CAS、证据 hash 和报告继承继续使用原有存储校验。未配置 storageRoot 的旧模式仍默认使用 projectRoot。

runtime 接受 auto、read-only、workspace-write 和 danger-full-access；auto 默认继承主会话，其他值是权限上限。Shell 不允许后台驻留或参数提权。Linux 下状态目录还不能位于原生执行器可能开放写入的 `/tmp` 中。非完整访问模式的文件工具路径限制在工作区内；完整访问允许任务授权范围内的其他普通路径，插件私有状态与凭据仍受保护。

`runtime.protectPrivatePaths` 默认 true，保护 `storageRoot`、执行状态目录及可选的 `privateReadRoots`（最多 16 个已有绝对目录）。状态根包含工作区时，仅重新开放当前工作区，其他私有子目录保持隐藏。原生文件工具拒绝凭据路径、临时文件及符号链接别名；Shell 和搜索使用每次工具调用独立的 Linux 挂载视图，私有目录为空且只读，当前工作区保留原权限。DSH 托管凭据的专用父目录采用只读快照，保留非秘密工具链/配置，排除凭据、锁及原子替换临时文件；宿主刷新凭据不会把新文件暴露给正在运行的命令。宿主模型请求继续在此视图之外读取已登录凭据。

Shell/搜索的这项保护要求 Linux 及可用的 `/usr/bin/bwrap`，不可用时在模型请求前拒绝；仅文件工具不需要进程挂载能力。自定义凭据文件应位于专用目录，不能直接放在项目根或其祖先目录。可信宿主可显式设置 `protectPrivatePaths: false` 保留旧行为，记录会标明关闭。它保护指定私有路径，仍允许普通宿主文件与工具链读取；不提供通用网络隔离、同用户进程隔离或所有秘密自动发现。外部工具/远程 MCP 的内部权限仍由各自宿主管理。包装只在该 direct 工具调用的异步作用域内生效，不更改其他聊天的默认发送、工具与读取策略。

适配器会使用真实审批服务，保留 approval/asked 与 approval/decided 日志；无答复通道时拒绝，不伪造授权。Goal、TODO、正式事务图与动态报告提交仍有不同含义；叶任务没有因此获得控制器的状态写权限。

## 控制器入口

默认 `interaction.mode: interactive`、`interaction.orchestration: true`。未启用时完全沿用原生对话、工具、任务清单与 Plan 模式，无需模型登记路线或判断项目规模。只有用户实际输入 `/task-graph [任务说明]` 后，程序才询问三种模式并按选择进入原生、独立任务图或完整预规划流程。旧的模型模式选择和路线工具从模型工具面隐藏，派发层也拒绝调用；已核验选择与既有图继续沿用，不重置历史。

完整模式在开始规划前询问一次“规划完成后直接执行（推荐）”或“先展示规划，等我确认”。真实选择持久化为 `afterPlanning`；无答复不按推荐项授权。Slash 命令只有实际参数被写为用户任务，插件的流程说明装配为程序上下文，不能把一般暂停提示改写为本次用户要求。

独立规划会话接收原始用户内容（含附件块）、项目指令、当前权限、基础条件探查指引、允许的叶工具与完整提交模板。延后启用时还会封存 `/task-graph` 之前的可见讨论、工具调用和结果（含原生计划提交及批准结果），保留来源序号与调用关联；不转入系统/运行时提示词或私有思考。短历史直接以标明来源的证据装入，长历史提供索引并用 `dynamic_context_planning_history` 分页读取或搜索。助手建议不自动成为已确认要求，工具反馈不成为指令。快照校验固定，恢复预规划沿用原快照；此前已经启动的旧规划器保留其原装填方案。它开放原生 Bash、读取、搜索、可用的资料查询和人类澄清，禁止原生任务清单、文件修改工具、普通子 Agent、叶调度和共享修改工具。Bash 用于核对对象可访问性、授权适配性、必要能力/资源及影响规划的基本结构；不按命令字符串设置白名单。用途由提示词约束，具体执行仍受宿主权限和审批约束；不能宣称 Bash 在语义上被程序证明无副作用。原生 Plan 下继续保持只读策略。模型可在同一规划历史中修正格式错误，不要求整份重做。

提交成功会结束规划回合并拒绝同批后续调用。程序等待提交结果持久化及规划器退出，再读取最新图，按 `legalNext[0]` 串行调用现有执行器；每个叶之后仍运行原有验收、计划复查及必要的修订/审计。主会话只交互、展示状态和处理阻断，不负责猜测是否应该调用 `run_next`。完整模式的 schema 过滤与执行 guard 使用同一准入集合，覆盖 DSH 原生 `restrict()` 不会过滤的 Agent 自身工具。

`auto_start` 不再额外请求规划批准；`await_approval` 停在 `WAITING_PLAN_APPROVAL`，使用 `dynamic_context_workflow({action:"approve"})` 询问对当前 workflow/图版本、校验值及用户任务约束的确认。原生 Plan 模式和具体操作审批各自生效，`approvalPolicy:ask` 不等于“规划后等待”。原生 Plan 退出事件会在下一安全步骤边界触发已授权的交接。

生命周期保存在根会话中，可通过 `dynamic_context_workflow({action:"status"})` 查看。未完成规划或已知安全检查点用 `action:"continue"` 显式继续；`action:"pause"` 和原生取消会阻止继续派发。用户插话也会停止当前流程以处理新要求。恢复原规划记录保留已完成的探查；未知工具结果不能重放。进程重启、安装新版或普通状态询问都不会凭持久化队列自动续跑。已提交但没有可靠规划结果收据的图必须先核对；可从可信规划日志恢复交接收据，但不会重新调用模型生成替代图。无就绪叶不等于完成，活动叶、未决监督和缺图恢复仍阻止下一叶。任务图完成不等于 Goal 独立验收。

当完整联动流程在监督结束后出现 `NO_READY_LEAF`，新增的阻塞处理者负责选择证据支持的返工、短式蓝图复核信号，或经独立审核后等待用户恢复。旧执行/验收/补正/复查提示词不变，旧报告和执行事件不覆写。角色限定工具、两份报告模板、校验及恢复边界见 [阻塞处理协议](BLOCKAGE-HANDLER.md)。

原生模式与独立任务图模式保留各自原有执行方式。仅任务图的已有图不会被补造为双图；旧联动图没有新生命周期策略时需显式补齐后再继续。`interaction.orchestration:false` 是保留旧手动控制器工具流程的回退配置，测试中单独验证；它不提供独立预规划和程序交接，但用户启用入口同样仅限 `/task-graph`。`standaloneGraphPresence` 与 `status.graphPresence` 继续区分从未建图和提交后丢图。

共享事实仍需节点绑定和对应工具授权，叶按实际装配 ID 读写；报告修复继续装填完整原上下文。上述更新不增加请求数、时长或阶段额度限制。fake 验证确认流程、工具和装配边界；模型分类准确率、探查适量性及长期注意力效果仍需真实会话观测。

受信宿主或 CLI 使用 `interaction.mode: host`，自行负责控制器选择和调度；CLI 默认 host 且不暴露对话工具，仍挂载必需的任务图服务。`native-guarded` 仅允许 host 模式且显式关闭控制工具。

手动控制器及 host 模式在 `direct.durable: true` 时另提供 `dynamic_context_pause` 和 `dynamic_context_resume`；新联动主会话统一使用 `dynamic_context_workflow`。暂停请求等待完整模型/工具交互结束，暂停本身不提交报告。恢复须携带状态中的最新检查点 checksum 和图 revision，并重新关联原控制器。状态中的 `resumablePhase` 只表示阶段允许恢复；仍须取得独占执行权，正在运行的进程不会被抢占。

durable 模式还提供 `dynamic_context_reconcile` 和 `dynamic_context_maintenance`。前者只能调用宿主已注册的可信核验器，按带 hash 的回执将已停止的未知任务关闭为 UNSATISFIED；不能自我批准或声称成功。后者先生成清理预览，再用精确 planChecksum 清理未引用的中断残留，保留已提交历史。程序端对应 `reconcileActive`、`collectOrphans` 和 `registerReconciliationVerifier`，详见发布指南。

宿主配置示意（需已有 DSH 工具执行服务，状态根目录应预先建立）：

## 按角色登记工具阻塞规则

宿主插件可以用同一个 `dynamicContextToolErrors` 服务为控制器、预规划、叶执行、监督审计、报告、引导及压缩角色登记规则。匹配角色 ID、实际工具 ID 与结构化错误码，`when` 可再限制 `/isError`、`/error`、`/value`、`/meta` 下的精确字段。普通工具错误会返回给当前 Agent。命中规则会保留实际调用回执，并等待用户通过任务图继续入口确认。

```js
const unregister = ctx.get('dynamicContextToolErrors').register({
  pluginId: 'example-plugin',
  ruleId: 'audit-attachment-missing',
  role: 'group_audit',
  toolId: 'read_image',
  errorCode: 'ATTACHMENT_NOT_FOUND',
  reason: '检查本次终审引用的附件是否可以恢复。',
})
ctx.effect(() => unregister)
```

既有省略 `role` 的规则保留原 Direct 执行桥的适用范围。登记按运行边界取快照。用户确认后，程序继续使用已存的模型与工具回执。回执缺失、身份校验失败和用户取消依然由程序按已有恢复条件处理。

Direct 在准备 `read_image` 的下一次请求时，读取附件失败会在第一次尝试后重试三次。耗尽时，同一个工具调用 ID 会带结构化失败结果进入下一次请求。原始工具回执仍保留，当前请求会明确标出图片未完成检查。为该角色登记附件错误的阻塞规则后，重试耗尽可转为等待用户确认。

## 检查点、压缩与恢复

默认不启用持久恢复。启用 `direct.durable: true` 后，运行器在 HTTP 或工具开始前持久记录意图，交互完成后保存不可变快照、链式记录和原子 head。Linux 使用 `/usr/bin/flock` 的文件描述符模式取得内核独占锁；辅助进程随即退出，运行器自身持有描述符直到释放或进程退出，没有使用过期 PID 文件猜测所有者已停止。

| 检查点阶段 | 恢复行为 |
| --- | --- |
| `READY` | 完整交互后的边界；保持原 attempt，从下一次请求继续 |
| `PAUSED` | 已停止的安全边界；需要显式恢复 |
| `REPORT_READY` | 完整报告已收取，尚未提交；直接提交已保存的报告，不再请求模型 |
| `PREPARING`、`MODEL_PENDING`、`TOOL_PENDING`、`BLOCKED` | 拒绝自动恢复，不能排除请求或工具已有部分效果 |
| checksum、归档、链或提交尾部异常 | 拒绝恢复，不能退回较早的安全快照重放 |

实际调用示例：

```js
const paused = await ctx.dynamicContext.runNext({ expectedRevision, sourceAgent, pauseAfterRequests: 3 })
// 返回 paused:true 时，尚未完成当前叶任务。重开同配置的运行器后：
const result = await ctx.dynamicContext.resumeActive({
  expectedRevision: paused.revision,
  checkpointChecksum: paused.checkpoint.checksum,
  sourceAgent,
})
```

若响应已正常结束，`runNext` 会直接返回报告；调用方须先检查 `paused`。运行过程中也可调用 `pauseActive({ expectedRevision })` 请求在下一安全边界暂停。普通 `runNext` 不接管已有 ACTIVE，恢复必须走显式接口。请求次数、已使用调用 ID 和压缩次数按整个任务累计；`timeoutMs` 按每次执行/恢复计时。

恢复时重新核对上下文、配置、插件和复用的本地策略源文件、工具定义、当前控制器权限/输入/Goal、目录指令与技能。新建真实原生 Session，以公开 fork/seed 接口继承旧事件并记录来源，保留同一逻辑 attempt；当前时间与物理 Session ID 重新采样。**原生文件观察 gate 是内存状态，不随 Session 事件恢复**：编辑或覆盖既有文件前必须重新 `read`；归档中的读写结果不算新的文件观察。更换原生运行时安装或外部工具的隐含配置须重新验收，函数/声明指纹不证明闭包和外部服务完全相同。

原有提取式压缩需另外配置下列字段，并在宿主 `allowedTools` 和每个叶任务绑定中都显式加入 `dynamic_context_source_read`，同时启用 `state` 模块：

```js
direct: {
  // endpoint、runtime 等仍需按上例声明
  durable: true,
  compaction: {
    triggerCharacters: 14000,
    retainRecentExchanges: 0,
    maxCompactions: 4,
    maxCheckpointCharacters: 10000,
  },
}
```

触发条件是可变历史超过阈值，或整个请求将超出输入字符预算。只在完整工具交互边界压缩，保留最初 system 和任务绑定；旧 assistant/tool 原文写入当前 attempt 专属归档。生成的提取式检查点保留调用配对、参数和结果 hash、局部预览、来源角色、观察到的验收词与历史证据含义；后续发现的目录指令和已加载技能正文完整保留。无法容纳这些约束或无法缩短输入时停止，不截断约束。连续压缩保留此前归档引用，恢复后仍可回读第一次归档。

`dynamic_context_source_read({ archive_id, message_index, offset, length, field })` 按 UTF-16 字符位置读取 `content` 或 `tool_calls`，单次最多 8000 字符。归档 ID 是完整文件的 SHA256，仅当前任务尝试已登记的 ID 可读取；后继任务即使知道 ID，也不能借此取得前序原始工具历史。任务间仍只继承声明的报告。检查点明确标为程序生成的历史资料，不能成为新的用户授权或当前 PASS 结论。

提取式策略将 `context-memory` 的纯证据标签/角色规则随包分发，不调用辅助模型。输入预算与测量均针对同一份 direct 消息和工具定义，但字符数不是模型 token 数。批量快照/归档受 `direct.maxJournalBytes` 约束，默认 128 MiB，预留小型意图/对账记录空间；`collectOrphans` 仅回收无引用残留，完整已提交历史不自动删除。

## 原生压缩适配（工作区未发布）

可选择 `direct.compaction: { strategy: 'dsh-native', contextWindow: 1048576 }` 并开启 `direct.durable`。以官方 DSH DeepSeek 默认通道为对照时，应核对 `maxOutputTokens: 256000`、思考模式及主会话有效档位，并为百万窗口配置足够的字符、HTTP 和持久化容量。`direct.reasoningEffort` 默认 `auto`；需要固定对照档位时才显式设为 `high` 等值。窗口必须来自实际模型目录，不应把 DSH 的回退容量或模型输出能力误当作当前路由的请求默认值。

DSH rc.5 的触发线为 `floor(min(0.8W, W - O - 65536))`，尾部保留量为 `floor((W - O) * 0.16)`。`W=1048576, O=256000` 时分别为 **727040** 和 **126812**。direct 每次都显式发送输出上限，因此输出预留直接取 `maxOutputTokens`，不允许另填矛盾的预留值。

策略先调用同版本 DSH 的公开文本 token 估算器判断压力，再按原生规则裁剪超过 8192 个 Unicode 码点的工具结果（保留头 4096、尾 1024）；仍有压力时保留完整的近期工具交互，并调用模型摘要。摘要指令和检查点开场白逐字复制 pristine rc.5，附 MIT 许可；辅助请求保留原 system、任务前缀和工具定义，输出上限为原生 65536。所有辅助调用进入费用观察器和持久记录，摘要中的工具调用不执行。

适配差异：初始任务绑定在 B 组继续保持固定；检查点增加宿主来源信息和完整驻留规则；尾部重复当前任务绑定，防止旧工具调用形式主导续作。共享上下文、动态上下文图提示词、角色提示词保持原文，运行中共享事实读写所在的完整工具批次也不裁剪、不替换为摘要。保护内容本身放不进窗口时，明确报告容量不足，不能以压缩这些内容继续运行。

历史内容先分别压缩、再组合装入：辅助角色按原 JSON 位置归档历史字段，过大的字段分段压缩；执行通道按完整工具交互分段，摘要请求自身也必须通过窗口检查。原生压缩提示词、65536 输出上限与阈值公式不变。宿主 tokenizer 可用时使用其测量；缺失时容量准入采用 UTF-8 字节上界，可能较早压缩，不能把这个上界称为实际 token 用量。关闭自动压缩也不关闭已知窗口的发送前检查；第三方模型可通过 `direct.contextWindow` 声明窗口。

启用原生压缩与执行运行时时，自动提供当前执行归档的 `dynamic_context_source_search` 和 `dynamic_context_source_read`；辅助角色压缩后提供 `dynamic_context_search_evidence` 和 `dynamic_context_read_evidence`。按原文进行大小写敏感的字面搜索，返回来源校验值、UTF-16 位置、准确读取参数与分页游标。搜索覆盖裁剪前的完整原记录，包括只裁剪工具结果而未调用摘要模型的情况。这些能力只读取已交给该执行或角色的证据，不扩大工作区权限，也不授予其他任务历史的访问权。摘要仅用于导航，重要结论应回查原文。

已确认的上下文超限拒绝与未知响应分开登记；允许一次强制压缩后重试，重试不重复工具副作用。旧式全量请求的手动恢复保留既有未知记录与账务状态，在无账务挂起约束的明确恢复授权下重新准备压缩输入，不把未知请求改写成成功。未知响应仍需显式恢复或账务核对。图片、原生手动压缩入口及原生会话投影互操作不在此适配范围内。

宿主可通过 `registerInputMeter({ version, measure, observe })` 实现统一费用保护。5 元烟测先按完整输入窗口及原生输出上限预留费用，再按最终 usage 结算；流式字节数不是 token 数，不再用于提前截断输出或思考。可选同步 `observe` 回调用于在费率变化时重算总额度占用，不另设单次或阶段额度。辅助请求和普通请求共享连续 `ordinal`；普通工具循环另记 `taskOrdinal`。出现未知回执时不应释放费用占用或自动重放。

2026-11-10 追加到累计 5 元后，三轮官方默认参数的真实压缩与续作均达到严格 **24/24**，覆盖两种条款分布和完整原始日志；原始日志轮摘要请求实际输入 712,597 tokens。复用同一摘要与尾部、仅移除任务提醒的负对照再次请求历史工具，未交付答案，事实保持程度无法评分。保留尾部任务提醒；这只是当前合成重放场景的结果，不能证明长任务注意力或普遍收益。详细证据见工作区 `docs/audits/dynamic-context-native-compaction-20261110-cny5/REPORT.md`。

## 任务图联动与 DeepSeek 协议

`interop.enabled` 只能为 true。任务图服务为必需依赖，未就绪时插件等待，服务丢失或替换后阻止后续执行。插件按契约 `dsh-taskgraph-workflow-v1` 注册一个工作流；`interop.workflowId` 可显式指定，否则按状态目录生成。服务加载先后顺序均可，重复工作流标识拒绝覆盖。`ctx.transactionGraph.dispatchWorkflow(controllerAgent, reference, operation, request, signal)` 使用同一个联合账本执行操作；原来的正式事务账本和 Web 面板不被镜像或改写。公共调用示例见配套任务图包 README。

`direct.api: deepseek` 配合默认 `direct.protocol: auto` 使用与本维护线原生 DSH 相同的 **DeepSeek Messages API**。推荐 endpoint 为 `https://api.deepseek.com/anthropic/v1/messages`；此前示例中的官方 `/chat/completions` 和 `/v1/chat/completions` 在该模式下自动转换到同源 Messages 地址。自建网关应明确提供以 `/messages` 结尾的地址。旧网关或历史对照可显式选择 `protocol: chat-completions`。通用 OpenAI-compatible / llama 仍使用原协议，不增加 DeepSeek 专用字段。

`reasoningEffort` 默认为 `auto`，也可显式设为 `off`、`low`、`high`、`max`。auto 让预规划、叶执行、返工、验收、计划复查、图更新及审计、阻塞处理、组终审与最终报告统一继承主会话有效档位；未显式指定时读取该会话路由的提供器默认值，不恢复创建 Agent 时留下的旧值。无主会话时读取插件路由的默认值；缺少元数据时，Messages 与原生一致使用 high，兼容 Chat 模式则留给接口默认值。auto 不会传给服务端。

| 有效档位 | Messages 请求 |
| --- | --- |
| off | `thinking.type: disabled`，不发送 `output_config.effort` |
| low / high / max | `thinking.type: enabled`，`output_config.effort` 为对应档位 |

当前原生 DSH 适配器没有按档位附加不同的思考提示词；本插件同样不追加这类文案。动态上下文仍拥有自己的任务、角色、工具和证据装配，不调用原生默认提示词提供器。Messages 不发送 Chat 专用 `reasoning_effort`、`stream_options` 或 `response_format`；角色 JSON 格式继续由现有角色提示、标准模板、程序验证和定点返修流程保证。API Key 使用原生的 `x-api-key`，账户登录使用原有 `x-dsh-auth-token`，压缩请求带原生压缩标记。

每个 direct 执行段或独立角色在开始时记录有效档位；该操作的普通请求、压缩和暂停恢复沿用快照，保证持久化请求不会换参重放。主会话修改档位后，新执行段与新角色继承新值。原生预规划在创建或恢复时读取主会话设置。显式配置档位优先；`thinking: {type:'disabled'}` 强制关闭，继承到 off 也会关闭。不支持的跨模型档位返回明确错误，不暗中降级。这里对齐的是 API 与推理控制；已记录操作的恢复策略仍由插件负责。

Messages 思考块的顺序、文本与签名原样保留，并在工具续接时回传；空思考或没有思考块也可正常执行，不伪造内容。归档仍提供原始推理正文。缓存读取、缓存写入与普通输入按 Messages 原生用量含义转换为现有计量字段，原始用量另存回执。请求日志和摘要校核针对实际发送的 Messages JSON，输入计量器也接收实际发送对象。自定义计量器需要识别 `system`、块数组和 `input_schema`；旧计量器只支持 Chat 时应先显式保持兼容模式。Messages 仅支持原生已提供的 temperature 采样字段；其他采样字段需兼容模式，不能悄悄丢弃。

`responseModelAliases` 可显式允许服务端返回的模型别名，默认只接受配置模型；不自动扩展。记录服务端 request ID、response ID 和 usage，凭据不进入记录。显式输出上限支持到 393216；官方 DSH DeepSeek 提供器默认值是 256000（不是模型能力上限），单次执行超时可配置到 30 分钟；任务总请求数默认 4，可显式配置到 256。可选 `direct.reserveFinalReport` 使最后一次请求只允许报告，任何意外工具调用在产生效果前拒绝。

关闭压缩的大任务示例为 `examples/deepseek-no-compaction.patch.yml`：128 次调用、32K 输出、8,388,608 UTF-16 字符和 4 GiB 持久记录预算。输入字符、8 MiB 请求字节、实际模型 token 窗口及货币额度分别管理，不把字符数称为 token 数。完整请求在持久检查点中按 hash 引用独立文件，恢复时校验原始发送体；这是无损存储去重，不是上下文压缩。

宿主可注册 `registerInputMeter({version, measure})`，回调收到冻结的实际 payload 和取消信号，返回 `{tokens, method:'exact'|'estimate'}`。返回值连同计量器版本进入记录，版本/实现指纹参与恢复配置校验。只有 exact 才能满足可选 `maxInputTokens` 的硬预算；没有计量器或只给估计时拒绝使用该预算。服务端 usage 与发送前测量分开记录。

## 程序接口

`index.mjs` 导出 Cordis 插件与 `DynamicContextPrototype`。配置需要显式提供 `transport`、真实项目根、独立状态目录、模型标签、完整宿主提示及工具权限上限。`direct` 另需完整的 `direct.endpoint`，可配置凭据引用、generation、runtime 或旧 agentlessTools，以及请求与响应字节上限；不会自动读取 provider 的 endpoint。`provider` 在直接通道仅作审计标签，实际目标由 endpoint 决定。

启用后，宿主通过 `ctx.dynamicContext.submit(proposal)` 提交双图，通过 `ctx.dynamicContext.status()` 读取状态，通过 `ctx.dynamicContext.runNext({ expectedRevision, choice, signal, sourceAgent })` 执行一项就绪任务。sourceAgent 的输入只用于变化校验，不把其完整历史复制给 worker；宿主仍需在系统规则和双图中声明当前授权范围。`runtime-demo.mjs` 是实际工具接入示例，`testing/scenario.mjs` 与 `testing/harness.mjs` 保留最小合成配置。

未声明 hierarchy 的旧协议仅接受一个根容器及其直接叶任务，叶任务之间使用 prerequisite 边；新分层协议见上文。结构修订通过独立审批在同一事务中更新双图并保留旧上下文版本。任务进入 ACTIVE 先于模型请求；全部结果及执行记录保存之后才提交报告。模型报告始终标为 `UNVERIFIED_MODEL_REPORT`；任务图 COMPLETE 仅表示本次正常响应及报告提交完成，不能表示目标验收通过。

## 原型边界

这是独立、可安装的候选发布包，已提供联合建图、真实工具执行与任务图联动接口。现有生产事务图账本不参与动态执行；模型报告不因此取得正式事务证据或 Goal 验收资格。Web 界面仍由宿主原有入口提供。

direct 私有历史已验证连续压缩、有限安全边界恢复、可信宿主对账和任务切换。原生同一会话投影与原生压缩器互操作、任意 ACTIVE 自动判定成功、条件分支、实时上下文修改和真实模型质量仍未验收。原生 wire 校验暂限定文本及原生工具调用，未验收推理历史和多媒体的 provider 投影；直接通道也不等于完整 DSH Agent 功能。

fake llama 的回答、usage 数字均为合成数据，只验证上下文传递、请求与状态转换；不能据此判断模型理解能力、准确率、注意力改善或真实 token 成本收益。本原型不自动安装到现有 Web profile。

恢复验收针对本机 Linux 的单个进程 SIGKILL 和同一可信运行时安装；未做系统断电、文件系统损坏、跨机器迁移或真实模型服务器回执对账。结果未知的执行需要人工/宿主核对实际回执，不提供“强制成功恢复”开关。

## 总额度实验配置（未发布的工作区版本）

显式 `null` 可关闭 `maxRequestsPerTask`、整任务 `timeoutMs`、`maxContextCharacters`、`maxStateBytes`、`maxReportCharacters`、`direct.maxRequestBytes`、`direct.maxResponseBytes`、`direct.maxJournalBytes` 与 `direct.runtime.maxToolOutputCharacters` 的附加上限；省略配置仍使用原默认值。无界调用不能与 `direct.reserveFinalReport` 同用。`direct.runtime.nativeRequestControls: true` 使用原生 Shell 的 60 秒默认值、600 秒允许最大值及工具自身超时；`direct.streamIdleTimeoutMs` 可单独保留原生式流空闲控制，不充当整任务截止时间。

`direct.tracePayloads: references` 需要 durable 模式：每个实际请求完整保存在原文文件，trace/checkpoint 引用其路径和 SHA-256，内存只保留最新请求载荷。恢复仍逐一校验原文；未知请求/工具效果、图校验、路径权限和原子提交不因取消数量/体积上限而放宽。磁盘、内存及原生工具本身的能力边界仍存在。

正式实验准备使用独立、固定版本的原生 DSH A 入口，以及任务图联动 B 入口；配置、费用规则、评分和隔离边界见仓库 `experiments/dynamic-context-ab-v1/README.md`。该实验在共同外层文件系统隔离中运行；因本机内核拒绝嵌套用户命名空间，B 的实验配置显式关闭重复的 `protectPrivatePaths`。这只保护未挂载的宿主/对方/评分材料，不隐藏该臂自身的 `/state`，任务禁止读写该目录。插件默认私有路径保护仍启用；该实验不验证其对恶意 Shell 的防护。现有 rc.4 交付包未替换。

## 叶处置监督（0.1.0-rc.6）

自 0.1.0-rc.6 起，可在新建 durable direct 工作流中配置 `supervision: true`。每叶声明 `completion`，执行者提交 COMPLETE、BLOCKED 或 FAILED 的结构化请求。先受理本叶结果，再在持久化的调度门槛内倒查整图。只有版本绑定的复核信号会启动更新和独立审计。控制器通过 `continueSupervision`、`dynamic_context_continue_supervision` 或 workflow `continue_supervision` 恢复精确检查点。详见仓库 `docs/WORKFLOW_SUPERVISION_20261111.md`。

## 双角色联合修订（0.1.0-rc.5）

配置 `revision: {policy: {objective, requirements:[{id,text}]}}` 后，程序接口 `runner.revise({expectedRevision,reason,evidence,sourceAgent,signal})`、控制器工具 `dynamic_context_revise` 与 workflow v1 的 `revise` 操作接入同一流程。policy 由宿主从当前授权任务初始化，不能由上下文改写或沿用到无关任务。evidence 为项目内的 `{kind:'artifact',ref,sha256}` 列表；私有账本、凭据、符号链接和硬链接不能作为向模型发送的证据。

updater 与 reviewer 使用各自新请求和独立运行标识，严格串行。后者不接收前者的对话/思考历史，只读取固定合同、原图、证据、完整提案及程序校验结果。拒绝理由可由控制器作为下一轮待审反馈，仍须重新审批。上下文不会授予工具权限，审批也不会完成 Goal。

修改只能在没有活动任务的安全边界提交。程序保留已执行节点和使用过的上下文闭包；修正未来任务时使用新节点。两张图、审批收据、旧上下文版本和失效报告状态在同一 CAS 中提交；批准 hash 绑定实际完整候选内容。审批期间证据、授权或 revision 变化都会拒绝提交。

报告仍绑定实际执行时的 contextVersion。`invalidateReports` 会传递到依赖这些报告的已提交报告，未来绑定不得继承失效报告。历史记录保留，不将原失败/未验收结果改写为成功。未修改上下文可按 `{key,retain:true,sha256}` 引用，由程序核验并复制原文。每个角色请求及结果在私有 `revisions/` 目录中持久记录，未知模型结果阻止后台自动再次请求；交互模式的显式接续规则见下节。

`status()` 和 workflow 读取结果公开上下文版本与报告的 INVALIDATED / UNVERIFIED 状态。SHA 只证明证据文件身份和完整性，不能代替语义验证。未知角色请求由 `revisionRecovery()` 提供元数据，仅受信宿主可通过 `abandonRevisionRole()` 及专用对账证明将其封存为 ABANDONED_UNVERIFIED；原记录按字节归档，图不改变，费用预占不由插件释放。模型没有这个恢复入口。

配置后，控制器得到修订触发说明与当前合同；worker 得到提交证据及阻塞报告的说明，不取得控制器工具。完整设计见仓库 `docs/GRAPH_REVISION_WORKFLOW_20261111.md`。真实模型质量和边界仍以专项报告为准。

## 交互流程暂停与接续（本地待提交）

完整联动模式通过任务图的通用控制接口显示当前阶段、模型/工具步骤和更新时间。预规划尚未提交图时也显示状态；父会话暂时空闲不停止轮询。折叠面板及全屏面板都可操作暂停/继续。

- 正常暂停完成当前模型响应和该响应内已开始的工具批次，在下一次模型请求前停下；压缩、报告补正、验收、计划复查和图修订角色也遵守该边界。原生停止仍可以立即中断。
- 正常继续推进保存的下一步；意外中断继续核对排他锁、图版本、检查点、工具定义、项目指令及授权。丢失响应的模型请求可显式重试。已完成工具保留回执，缺少最终回执的工具标记 UNKNOWN，未开始的标记 NOT_EXECUTED，交由模型结合当前成果判断；程序不重放工具。
- 重载插件或重启 DSH 不自动继续。没有暂停标记的旧活动流程显示为意外中断。缺图、损坏图和不能证明身份一致的检查点继续阻止推进。
- 报告被退回后由程序串行接续补正、验收和计划复查；完全相同的补正/退回状态停止自动循环，保留活动叶等待处理。
- 时间、运行时观察、工具目录和插件状态通知不算新的用户授权。真实用户/开发者/系统指令、权限、工作目录、Goal 与模型配置仍受校验。旧版摘要只能用精确历史前缀证明兼容，不能直接重置摘要。

已完成的压缩/角色响应在恢复时复用，未知请求的费用记录保持未知；启用外部修订账务接口时，仍要求先完成其原有对账，不能用继续按钮释放预占。对于本地已知旧构建，`recovery-compatibility.json` 固定源文件指纹，且仍要求配置和权限不变；任意其他代码/配置变化不在兼容范围内。旧原始执行日志保留，历史事件顺序修复只作用于恢复时的继承副本。

可用 `node --test test/web-workflow.test.mjs` 跑真实 DSH Web RPC + fake backend 回归。可选浏览器回归为 `testing/browser-workflow.mjs`：设置 `DSH_TEST_BROWSER_MODULE` 指向单独安装的 Playwright `index.mjs`，设置 `DSH_TEST_CHROME` 指向 Chromium，再传入截图输出目录。测试自行创建隔离配置，关闭真实模型提供器。

## 后台执行详情（本地待提交）

原会话的主消息区显示预规划、叶执行、结果验收、计划复查、图更新、修改审计和压缩阶段的实际输出。插件把展示记录投影为 DSH 原生 `assistant-step` 和 `tool-call` 节点；思考折叠、Markdown、工具卡片、终端输出、文件结果及“查看”轨迹入口均由已有前端处理，不另建样式或渲染器。任务图面板只保留图、状态与暂停/继续按钮。模型思考沿用原生折叠设置，展开后可看实时片段；模型未返回思考时仅显示运行状态。终端结果在原生工具返回后显示，尚未接入运行中的 stdout 流。

展示缓冲约 150 ms，持久化到独立的 `execution-view-v1`，再通过主会话中可忽略、无 `surfaceOp` 的插件日志事件传递给原生 Chat。程序不会伪造主会话的模型回复或工具执行回执；这些事件不进入模型消息、权限摘要、验收和账务。模型输出、工具参数和结果会进入本地展示记录，系统提示词、请求头及凭据不会被主动复制。

刷新与重启后重用已保存的展示事件，不重复追加相同版本。首次查看旧流程时，从其规划会话、direct trace 和角色回执导入已有输出，并向主会话追加展示事件；保留原日志前缀及子会话、trace、账本文件，不改写原始执行证据。不恢复过去从未保存的流式片段。未完成记录标为中断，缺失回执不显示为成功。突然断电可能丢失最后一段未落盘的展示片段；执行事实仍以原始回执为准。独立只读接口保留 40 条分页、8 KiB 预览与 32 KiB 正文分页，用于检查与兼容读取，不是主会话的第二套 UI。

## 终端超时与原生日志闭合（本地待提交）

已确认旧缺陷：一次模型回复声明多个工具，前台命令超时后被 `DIRECT_RUNTIME_SHELL_NOT_COMPLETED` 升级为执行器退出；清理直接写 `step/end`，而同批未开始的调用没有配对回执。文件本身仍可解压、解析，但 DSH 的生命周期校验报 `step/end leaves unresolved tool call`，继而显示日志损坏。

修复分为三个位置：已确认结束且隔离正常的前台命令超时保留原输出、退出状态和部分副作用提示，同批剩余调用返回 `NOT_EXECUTED`，让模型先检查成果；参数或调用 ID 不合法的整批回复只保留在原始 wire trace，不先写入无法配对的原生执行记录；其他必须中止的路径在关闭步骤前补齐 `NOT_EXECUTED` 或 `UNKNOWN` 回执，不执行补记的工具，不假定成功。取消、隔离拒绝、隔离器失败和效果未知仍保持阻断。

对于已存在的同类损坏，显式继续时只允许使用受检查点前缀约束的 trace 副本，确认是最后一个 aborted 步骤提前闭合的已知形态后，在继承副本中插入缺失回执，并用 DSH 原生日志校验器验证。原始文件不重写，已执行工具不重放；其他类型的损坏不会套用此修复。升级或打开页面本身不恢复真实任务。

## 报告局部补正与统一性能统计（本地待提交）

报告补正仍装填原有完整上下文、原报告、执行证据和退回理由。新增 `dynamic_context_read_report`、`dynamic_context_rewrite_report`、`dynamic_context_submit_report`：用 JSON Pointer 选择字段，或用唯一匹配的原文片段修改格式错误；通过草稿 revision 防止过期修改，同批修改原子应用。可只修正一个测试引用、SHA 声明或文字段落，再直接提交组装好的报告，无需重新输出整个 JSON。歧义、缺失位置、版本冲突均返回具体错误，草稿不变。工具只改当前声明；原始证据、图及成果文件不变。提交后仍经过原有静态核对和独立验收。原有完整 JSON 回复方式继续可用，暂停和重启会从工具回执重建草稿。

原生消息区底部统计扩展到当前会话涉及的所有模型请求：前台、关联预规划、后台执行、报告补正、验收、计划复查、图更新、审计、压缩、原生辅助请求及嵌套子 Agent。原生已统计的主请求不再重复加算；关联子会话汇入父会话，独立会话和普通分叉仍分别统计。累计 token 使用提供器返回的 usage，区分未缓存输入、缓存读写和输出；思考 token 不在输出之外重复相加。后台步骤和工具耗时补入原生统计，同一个子会话工作轮只计一次；同会话的辅助请求增加步骤，不凭空增加工作轮。TPS 以输出 token 与有效生成耗时加权计算，不简单平均每条请求的 TPS。

上下文占用与窗口展示最近一次实际请求的数据，不累加不同会话的窗口；未返回 usage 时只显示请求侧估算的当前占用，不将估算加入累计 token。旧流程可从既有 trace、角色回执及规划日志补记已知 usage；没有记录的历史首 token 时间与耗时保持未知，不编造 TPS。统计记录使用独立、可忽略的日志事件，刷新/重启去重，不进入模型输入、权限或账务核算，也不影响总额保护。

前后台模型输出的 JSON 默认折叠，并标注执行报告、双图、验收结果等类型；展开内容继续使用原生 Markdown 和复制逻辑。普通说明文本和原生思考折叠逻辑保持原有行为。性能区沿用原生组件、设置和样式。

后台上下文压缩摘要也默认折叠，标题为“上下文压缩结果 · 第 N 步”，生成中、中断和失败时另有状态标记。点击展开可读完整原文，流式更新保留当前展开选择，重新打开页面后默认折叠。分类来自请求阶段，不依据摘要正文猜测；摘要即使包含 JSON 也仍标为压缩结果。此规则仅改变主会话的显示，不改变模型输入、原始证据、压缩策略或执行状态。

本地 DSH 0.2.1-rc.5 的渲染器没有公开的原生组件适配入口，因此临时启动器会调用 `scripts/patch-native-presentation.mjs` 安装一个显示层兼容入口。该脚本只接受已核对的上游版本和文件 SHA，保留原生 slot、子组件所有权和参数绑定；可重复运行，遇到未知修改会停止而不会覆盖。插件未提供适配时直接使用原组件。这一兼容补丁目前只验证本机版本，其他维护分支尚未移植，本地改动尚未发布。

## 缺图与恢复

| 可验证状态 | 处理 |
| --- | --- |
| 从未提交双图，只有任务图提案 | 切换为独立任务图，返回原有 create/read 工具及参数；由真实原生工具边界提交，不虚构上下文 |
| 从未提交双图，只有上下文图 | 报错，询问是否回退原生；无答复不回退 |
| 既有独立任务图，没有上下文图 | 继续原有任务图；明确提示尚未进入双图模式，不替换进度 |
| 双图曾提交，任务图、上下文图或文件后来缺失/损坏 | 阻止推进、重建和自动降级，展示恢复状态 |
| 存在已核验提交快照 | 用户确认后原样恢复双图、报告、版本和活动尝试；保留损坏文件，不自动继续执行 |
| 提交见证缺失、冲突、首次提交中断，或无可靠恢复副本 | 保留现场，等待核对；不能推断为从未创建 |

每次联合状态修改保存 PREPARED/COMMITTED 见证及完整已提交快照，见证位于 storageRoot 下 `.dsh/workflow-witnesses-v1/`，与图文件分离。交互提交另向原生会话保存工作流提交收据。`dynamic_context_recover_graphs` 只在用户确认和排他锁成立时恢复精确快照；活动或未知尝试不解锁、不重放。单张图的后续缺失提案不能抹掉历史图，必须走修订流程。

旧 rc.23 文件没有新见证，读取时返回需要核对的状态，不自动导入、重建或跨版本恢复活动请求。旧版本实验保留在原环境。若图、见证及会话收据全部被删除，系统无法凭空证明曾有历史；应从外部备份核查。见证和副本是完整性与恢复依据，不是对同用户恶意篡改的签名证明。

## 本地待提交：校验与审计退回协议

模型声明、工具参数、执行报告、修改报告及审计结论统一提供可定位的校验反馈。唯一可确定的 JSON 语法规范化直接接受并保留原文与修复位置；含歧义的转义、重复字段、缺少分隔/边界等返回具体 JSON Pointer、UTF-16 偏移、行列。不会推测缺失内容，也不会修补持久化日志或证据。

目录成员、SHA、测试回执、引用、图拓扑及授权校验说明具体拒绝项与差异。目录报告支持单个总 SHA，也兼容旧的递归清单；两种格式不能在同一行混用。旧清单每行仍独立覆盖整个递归子树，子目录单列不能替代父目录的后代成员。

验收 RETURN、审计 REJECT/NEEDS_USER 要求 `issues: [{path,item,reason,expected?,observed?}]`；路径必须指向本次角色输入中真实存在的项目，缺项应指向其存在的父对象。格式或定位不合格先交回该审查角色；合格意见随原有完整上下文转给执行报告修复或图更新角色。通过结论不得携带未解决问题。

Direct 工具调用整批准入完成前不产生工具效果；被拒绝的声明和程序反馈单独留痕，只有绑定当前任务、尝试、上下文和响应摘要的精确宿主反馈可以进入下一次请求。原请求字节与原生控制保持不变，反馈随持久检查点恢复。报告修复仍提供局部重写工具；连续相同拒绝项不因改写无关措辞而被视为推进。正常暂停的旧角色在实际输入完全一致时保留原提示与已完成回执，新角色使用新提示。

### 目录快照与模板同步

`dynamic_context_directory_snapshot({path:"deliverable"})` 由宿主计算目录身份，返回 `directory`、`snapshotId`、`counts` 和限定说明。执行者只需把返回的 `directory` 原样放进 `executionReport.directories`：

```json
{"path":"deliverable","hashScheme":"dsh-directory-sha256-v1","sha256":"<工具实际返回的64位小写十六进制值>"}
```

上述尖括号是模板占位，不能当作实际 SHA。此行不要附带 `files` 或 `subdirectories`。每个文件的散列、完整成员表和原始快照由程序保存在私有状态目录；验收前与提交前均重新核对。若目录变化，会报告总 SHA 的期望/实际值，并在已有快照可用时列出新增、删除、修改的相对路径。目录摘要相同表示本协议覆盖的树身份一致，不等于成果符合语义验收标准，也不能证明两次检查之间从未发生过临时修改。

哈希输入为 UTF-8 字节序排序的相对路径、文件/目录类型、文件 SHA-256、Unix 权限位（包含特殊权限位），也包含根与空目录。时间戳、所有者和扩展属性不计入。符号链接、硬链接、特殊文件、受保护路径和既有工件策略禁止的文件会明确拒绝，不提供忽略列表。单文件容量沿用扩展已有的 1 GiB 工件上限。扫描期间若检测到变化则拒绝本次快照。

执行叶使用时需同时启用 `state` 模块、在宿主 `allowedTools` 和该叶 `tools` 中授权此工具。不会向已提交叶自动补入权限。新报告补正角色可以读取当前草稿已声明目录的快照，并用 `dynamic_context_rewrite_report` 只替换对应目录行，再提交草稿；成果文件不被修改。正常暂停的旧角色保留原工具集合，避免改变已完成请求的身份。新快照读操作保存独立回执，暂停恢复重放原观察，验收时重新检查当前文件。

执行与补正提示中的 COMPLETE/BLOCKED/FAILED 模板、目录工具描述、报告 schema 和静态验收共用这一格式。完整图审计与报告范围审计使用各自真实输入路径；后者用 `/changes/<序号>` 等定位，不再引用其输入中不存在的 `/proposal`。模板回归同时检查格式和可定位性。

内部新增验收协议与完整模板见 [ACCEPTANCE-PROTOCOL.md](./ACCEPTANCE-PROTOCOL.md)。仅新规划显式声明 verification.version=1 时启用；既有图不会自动迁移。

本地角色扩展与用户引导协议见 [ROLE-EXTENSIONS.md](./ROLE-EXTENSIONS.md)，涵盖 Skill 提示词覆盖、工具面注册、途中报告、即时改图和报告草稿工具。

## 原生设置页面（本地待提交）

在「插件 → 动态上下文」中设置新任务的权限上限、批准策略、推理强度、组嵌套层数、上下文窗口及额外请求/超时/字符上限。使用 DSH 原生表单、保存、恢复默认与版本冲突检查；不会重启插件。权限默认跟随主会话，角色职责和 Plan 模式仍独立生效。

偏好保存到 profile 的 `preferences`；首次显式启用完整任务图时保存所选值，已有任务及旧会话不会因设置页修改而改变参数。主会话中的权限切换仍实时生效。数值上限使用 -1 沿用文件配置、0 不额外限制；嵌套层数和窗口使用 0 沿用文件配置。原生单次请求控制、模型容量与宿主总额保护不受这些开关替代。模型凭据、服务地址、私有目录、角色注册及固定提示词等部署项仍由原配置管理。

DSH 不允许修改被启动参数覆盖的同一配置项。临时启动脚本会将动态上下文默认配置迁入可编辑的 profile，逐项保留用户覆盖；其他启动覆盖继续使用生成的运行补丁。首次迁移备份原 profile，再次启动不重复改写。
